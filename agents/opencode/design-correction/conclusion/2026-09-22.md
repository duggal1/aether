# Design correction pass — 2026-09-22 (opencode)

## What worked
- Full directive executed in Sources/BrowserUI only; `swift build` green, 0 errors, 0 warnings.
- 48/52 UI tests pass. The 4 failures are pre-existing (untouched files):
  - `AetherSymbol.bookmarks` is not a valid SF Symbol on macOS 27 (3 tests).
  - `AetherTextWeight.emphasis.usWeightClass` is 500, test expects 450.
- New appearance resolver (`Design/AetherChromeAppearance.swift`) is the single source for
  toolbar/address/icons/tab-text/suggestion colors. Injected only on the content column so the
  sidebar keeps its dark theme behavior.

## Decisions that could surprise the next agent
- Sidebar blur uses NSVisualEffectView `.sidebar` + `.behindWindow` (not withinWindow):
  withinWindow has nothing behind it to blur as the bottom layer; behindWindow genuinely
  diffuses the wallpaper, and the #171717@0.55 veil kills the green/yellow chroma.
- Root background is always `theme.chrome` (never Color.clear) — gutters read as chrome.
- Sidebar collapse is width-driven (0-width + clipped + opacity), never insert/remove, so the
  WKWebView (`.id(tab.id)`) is untouched.
- `AetherPopoverBackground` is now opaque card + black@0.25, no glass, no stroke. Only the
  omnibox suggestions panel keeps one glass layer under an appearance-aware fill.
- `AetherPalette.hairline` alpha is 0. Intra-card dividers use an explicit white@0.06 /
  black@0.08 literal (SettingsDivider, profile popover, command palette).
- New custom icons: engine, gps, zipCode, nearby, server, serverOffline, serverCrash,
  cloudDownload, tabsGrid. Zap/filter SVGs intentionally skipped (no rows need them).
- US flag is a native SwiftUI view (Settings/USFlagView.swift), shown only for countryCode US.
- Pinned shortcut pills moved from the fixed 200pt profile cluster into the tab ScrollView
  so the cluster never overflows.
